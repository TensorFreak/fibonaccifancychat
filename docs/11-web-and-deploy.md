# 11. Веб-интерфейс и деплой

Добавлены веб-страницы (регистрация/вход + чат) и HTTP-эндпоинты, чтобы вы с
коллегами могли зайти на сервис, зарегистрироваться и потестировать чат с нескольких
устройств. Всё проверено сквозным прогоном: регистрация/вход/изоляция, мультиустройство
(два сокета на один диалог получают эхо и живой стрим), сохранение истории в Postgres.

## Что появилось

**Страницы** (отдаёт сам FastAPI):
- `GET /` — вход/регистрация ([`app/static/index.html`](../app/static/index.html)).
- `GET /chat` — чат ([`app/static/chat.html`](../app/static/chat.html)): список диалогов,
  живой стрим токенов, авто-реконнект, «+ Новый».

**HTTP API** ([`app/api/main.py`](../app/api/main.py)):

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/register` | `{email, password}` → создать юзера, вернуть JWT; занятый email → **409** (атомарно `ON CONFLICT`, M3-review) |
| POST | `/api/login` | `{email, password}` → JWT |
| GET | `/api/conversations` | список диалогов пользователя |
| POST | `/api/conversations` | создать диалог |
| GET | `/api/conversations/{id}/messages` | история (только своя) |
| WS | `/ws/{id}?token=…` | чат (токен — JWT) |
| GET | `/healthz` | живость **с пингом Redis+Postgres**; 503 при мёртвой зависимости (L3-review) |

**Аутентификация:** пароль хранится bcrypt-хешем ([`auth.hash_password`](../app/auth.py)),
после входа выдаётся JWT (HS256, `sub=user_id`, TTL 7 дней). Его же использует вебсокет
(`?token=…`) и HTTP (`Authorization: Bearer …`). «Фейковая почта» проходит — подтверждения
email нет.

## Как это работает для пользователя

1. Открывает `http://<сервер>/` (через `caddy`, порт 80/443) → регистрируется
   (email + пароль ≥ 6 символов).
2. Попадает в `/chat`, автоматически создаётся первый диалог.
3. Пишет боту — ответ стримится токенами.
4. **Мультиустройство:** заходит тем же аккаунтом с телефона/другой вкладки → видит те же
   диалоги; сообщения и стрим ответа синхронизируются на все устройства (эхо `user_message`
   + durable-лента токенов). Обрыв/refresh переживается — см. [07](07-resumable-streams.md).
5. Каждый пользователь видит только свои диалоги (изоляция — [10](10-hardening.md), C1).

## Запуск (общий сервер / VM)

Всё уже описано в [`docker-compose.yml`](../docker-compose.yml): postgres, redis, api,
worker, summarizer и `caddy` (вход + TLS). Наружу открыт только `caddy` (80/443); `api`
и `redis` доступны лишь во внутренней сети compose. Все долгоживущие сервисы имеют
`restart: unless-stopped` — поднимаются заново после краха/ребута (H2-review); `caddy` также
проставляет заголовки безопасности (HSTS и др., см. [`Caddyfile`](../Caddyfile), L5-review).

1. Скопировать env и задать секреты:
   ```bash
   cp .env.example .env
   ```
   В `.env` обязательно:
   - `AUTH_SECRET` — длинная случайная строка:
     `python -c "import secrets; print(secrets.token_urlsafe(48))"`
   - `AUTH_DEV_MODE=false`
   - `LLM_API_KEY`, `LLM_API_URL`, `LLM_MODEL` — ваша модель.
2. Поднять:
   ```bash
   docker compose up --build -d
   ```
   Схема БД накатывается автоматически: одноразовый сервис `migrate` применяет миграции
   до старта api/воркеров (см. [13. Миграции](13-migrations.md)) — отдельных действий со
   схемой не нужно.
3. Коллеги заходят на `http://<IP-сервера>/` (через `caddy`).
4. Масштабирование обработки: `docker compose up -d --scale worker=4` (FIFO-порядок
   держит гейт по `seq`, см. [10](10-hardening.md), H1).

## Доступ по сети и HTTPS

Вход теперь всегда через сервис `caddy` (см. [`Caddyfile`](../Caddyfile)); `api` наружу не
публикуется (H3).

- **Быстрый тест по IP:** `SITE_ADDRESS=:80` (дефолт) → `http://<IP>/` работает сразу,
  вебсокет идёт по `ws://` (страница сама выбирает `ws`/`wss` по протоколу).
- **С доменом и HTTPS (рекомендуется):** задайте `SITE_ADDRESS=chat.example.com` в `.env` —
  Caddy сам получит и продлит сертификат Let's Encrypt, `http` редиректит на `https`, и
  страница откроет `wss://`. WebSocket Caddy проксирует из коробки.
- **Доверие X-Forwarded (H3):** uvicorn принимает `X-Forwarded-*` только от `FORWARDED_ALLOW_IPS`
  (дефолт — приватная сеть docker), а не от «*». Если ставите свой прокси на другом хосте —
  впишите его CIDR. Дополнительно Caddy **перезаписывает** `X-Forwarded-For` реальным адресом
  пира (`header_up X-Forwarded-For {remote_host}`, см. `Caddyfile`), а не дописывает к
  присланному клиентом — иначе клиент подделал бы свой IP, и per-IP рейтлимит `register`/`login`
  (#3) обходился бы сменой заголовка (брутфорс пароля + CPU-DoS через bcrypt).
- **CORS:** страница и API на одном origin, поэтому по умолчанию `CORS_ALLOW_ORIGINS=*`
  достаточно. Если фронт вынесете на другой домен — впишите его сюда.

## Замечания по безопасности (для реального контура)

- Смените `AUTH_SECRET`, держите `AUTH_DEV_MODE=false`.
- Ни Redis, ни Postgres наружу НЕ публикуются — доступ только из внутренней сети compose
  (C1). Раньше Postgres торчал портом `5432` наружу под учёткой из `.env` (по умолчанию
  `app/app`) — на сервере с публичным IP это открывало БД со всей историей и хешами
  паролей. Для локальной отладки при необходимости привяжите порт ТОЛЬКО к localhost
  (`127.0.0.1:5432:5432`, см. комментарий в `docker-compose.yml`). В проде задайте сильный
  `POSTGRES_PASSWORD` и синхронно — `POSTGRES_DSN`; при внешнем доступе к Redis — пароль на него.
  **Фейл-фаст (M3-review):** при `AUTH_DEV_MODE=false` старт отклоняется, если пароль в
  `POSTGRES_DSN` дефолтный/слабый (`app`/`postgres`/…) — БД со всеми хешами не поднимется на
  общеизвестной учётке даже во внутренней сети (см. `_guard_postgres_password` в `config.py`).
- HTTPS: задайте `SITE_ADDRESS=домен` — иначе (при `:80`) JWT и пароли идут открытым
  текстом. `api` доступен только через `caddy`, `X-Forwarded-*` принимается лишь от
  `FORWARDED_ALLOW_IPS` (H3).
- **Токен в URL вебсокета** (`?token=…`): ws-подключение по-прежнему передаёт JWT в query,
  а значит он может осесть в access-логах прокси. Под HTTPS канал зашифрован, но для
  жёсткого контура вынесите токен в первый ws-кадр/subprotocol (пока не сделано).
- Одновременные ws-соединения на пользователя ограничены `ws_max_connections_per_user`
  (H2, дефолт 20) — защита БД от флуда коннектов. Отказ → ws close `1013`.
- Ограничьте `CORS_ALLOW_ORIGINS` вашим доменом.
- Рейтлимит на `/api/register` и `/api/login` (защита от перебора) — стоит добавить на
  уровне прокси; в приложении пока нет.
